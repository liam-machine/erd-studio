Why Make the Switch?

Every advantage designed for modern data teams who live in code

01
🔀
Git-First

Single Source of Truth, Native Version Control

Your semantic models live in the same repository as your dbt code. When you add a column to a semantic model and implement it in dbt, both changes are in the same commit. Your PR reviewers see the full picture: the "what" (dbt code) and the "why" (semantic context) together.

Git blame, git bisect, branch strategies, code review - all your existing workflows just work. No syncing between platforms, no "export and commit" dance. SQL DBM approach: Maintain a separate cloud platform that must be manually kept in sync. Two systems = two places for things to go wrong.

02
🏗
Design to Build

Complete Design-to-Production Lifecycle

See your planned models (orange) right next to your built models (blue) on the same canvas. When you run dbt build and a designed model becomes real, the extension automatically detects it and updates the canvas. Columns sync too.

The extension reads your dbt test definitions to identify FK relationships between built models. If a relationship isn't tested, you'll know. Your semantic layer isn't just documentation - it's validated by the same tests that run in CI.

03
🤖
AI-Native

Claude-Powered Design-to-Build Pipeline

Because your semantic models are just JSON files in your repo, Claude Code can read, design, and build them without any APIs or MCP servers.

Use a Claude skill to generate a complete semantic model design from requirements. Review the visual result in the canvas UI. Then use another skill to scaffold the actual dbt models. The AI has full context of both your lineage relationships and semantic relationships in the same workspace.

Private

Offline-Capable, Data Never Leaves

Works on a plane. Works behind a firewall. Works in air-gapped environments. Your schema never touches external servers.

SQL DBM is cloud-only. Your table names, column names, relationships, and documentation all live on their servers. With dbt Semantic Designer, sensitive metadata stays exactly where you put it: your machine, your repo.

VS Code Integration, Not Another Tab

Your semantic designer opens in the same window as your dbt code. Cmd+click from the canvas to jump to the actual SQL file. Use your existing keyboard shortcuts, themes, and extensions.

Context switching kills productivity. With SQL DBM, you bounce between browser tabs and your IDE. With this extension, everything is one Alt+Tab away.

⏱
Smart Jobs

Domain-Based dbt Job Orchestration

Build dbt jobs scoped to specific domains. Tag models by domain so you can refresh customer data hourly while finance models run daily. Match your pipeline cadence to actual report usage patterns.

Stop running monolithic dbt jobs that refresh everything. Domain-aware orchestration means faster pipelines, lower compute costs, and fresher data where it matters most. Your semantic domains become the natural boundaries for job scheduling.
